# Contributing

Open an issue before implementing a feature so its milestone, scope and acceptance
criteria can be agreed. Small bug fixes can go directly to a pull request.
Read [PLAN.md](PLAN.md), [ROADMAP.md](ROADMAP.md), and [AGENTS.md](AGENTS.md) first.

## Development

```sh
uv sync --dev
uv run pre-commit install
scripts/check.sh
```

The core must work without torch or a GPU. Keep work within the assigned milestone
and record commands, results and artifact paths in `planning/Mxx-*.md`.
Before submitting, run `scripts/check.sh`: ruff, format check, strict core pyright,
schema/license drift checks and `pytest -m "not slow"` with coverage and a 60 s test timeout. Optional slow/model tests use `uv run pytest -m slow`.
When contracts change, run `uv run python scripts/gen_schema.py` to regenerate
MixScript v1/v1.1, TrackAnalysis and bench schemas plus the MixScript reference.
Update examples and tests. Use `uv sync --extra neural --dev` only for optional
CPU model tests; no weights are downloaded by this command.

For dependency changes, run `uv run python scripts/third_party.py --refresh`,
review the versioned metadata snapshot and native notices, then rerun the gate.
Unknown or disallowed licenses fail closed. Docs dependencies use `--group docs`;
run `uv run --group docs mkdocs build --strict`. Mark standalone runnable Python
or shell fences with `<!-- test -->`; tests execute each in a temporary directory.
Install pre-commit hooks for both pre-commit and commit-msg stages (configured
defaults). Audio outside synthetic fixtures and all weights are blocked.

Use conventional commits such as `feat(analysis): add beat cache`,
`fix(render): smooth gain ramp`, `test: cover silence`, `docs: explain timing`, or
`chore: update tooling`. Keep commits and PRs focused on the final change.

## Clean-room and reproducibility

Never copy code from GPL/LGPL/AGPL projects, including automix-engine, Rubber Band,
Essentia, madmom models, and libKeyFinder. Papers and documentation may inform an
original implementation. GPL tools may only be optional external-process backends.
Record every new dependency or model weight with its license and URL in
`THIRD_PARTY.md`; non-commercial weights must never be defaults.

Seed randomness. Identical inputs and MixScripts must produce identical rendered
bytes in the same supported environment. Never commit model weights or audio other
than tiny synthetic fixtures generated by code. Prefer generating fixtures in
pytest temporary directories; do not attach copyrighted tracks to issues or PRs.

## Pull request body

Use the repository template with these sections:

- **What** — the problem and resulting behavior.
- **Decisions** — relevant tradeoffs and scope.
- **Files** — key changed paths and their roles.
- **Tests** — commands, results, and milestone evidence.
- **Audio-or-screenshots** — licensed demos or synthetic evidence when relevant.
- **Open questions** — unresolved decisions, or “None”.

and that you will follow the [Code of Conduct](CODE_OF_CONDUCT.md).
